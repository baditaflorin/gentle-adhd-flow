# 0070 Documentation-Reality Alignment Process

## Status

Accepted.

## Context

README and ADR language can drift from shipped behavior.

## Decision

README features must be stated as a verified checklist. Claims without tests or direct manual verification are removed or moved to limitations.

Phase postmortems list known gaps plainly.

## Consequences

Visitors see what the app actually does, not what the architecture suggests it might do later.

## Alternatives Considered

- Keep aspirational README language: rejected because Phase 3 is about trust.
